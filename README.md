My work revolves around one principle:

## `04 // ARCHITECTURE`

```text
                         ┌───────────────────────┐
                         │      CLIENTS          │
                         │ Web · Mobile · API    │
                         └───────────┬───────────┘
                                     │
                                     ▼
                         ┌───────────────────────┐
                         │      CONTROLLER       │
                         │    HTTP Boundary      │
                         └───────────┬───────────┘
                                     │
                                     ▼
                         ┌───────────────────────┐
                         │       SERVICE         │
                         │ Business / Workflow   │
                         └───────────┬───────────┘
                                     │
                      ┌──────────────┴──────────────┐
                      ▼                             ▼
            ┌──────────────────┐          ┌──────────────────┐
            │    REPOSITORY    │          │   INTEGRATIONS   │
            │   Persistence    │          │ APIs · BPM · etc │
            └─────────┬────────┘          └──────────────────┘
                      │
                      ▼
            ┌──────────────────┐
            │       DATA       │
            │ SQL · NoSQL      │
            └──────────────────┘
```

The exact shape changes with the system.

The principle does not:

**dependencies should be intentional, responsibilities should be visible, and change should have a predictable blast radius.**

<details>
<summary><b>Architecture principles</b></summary>

<br/>

```yaml
boundaries:
  controller:
    responsibility:
      - transport
      - request validation
      - response mapping

  service:
    responsibility:
      - business rules
      - orchestration
      - transaction boundaries

  repository:
    responsibility:
      - persistence
      - query execution

patterns:
  - DTO
  - Specification
  - Builder
  - Factory
  - Strategy

cross_cutting:
  - centralized exception handling
  - validation
  - consistent package conventions
  - explicit enum management
  - reusable base abstractions where justified
```

</details>
